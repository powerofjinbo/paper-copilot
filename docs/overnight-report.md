## 1. 先解决你遇到的两个问题

### PDF 编译不出来

原因多半是 Mac 上没有装 LaTeX（`latexmk`），而演示模式本来就没有 LaTeX，以前点“编译”只弹一句话，看起来像坏了。

现在：

- **完整模式没装 TeX**：顶栏的编译按钮显示“未安装 LaTeX”。编译栏、按钮的弹出框和 PDF 面板里都有两三行安装命令：
  - Mac：`brew install --cask mactex-no-gui`（或者装小一点的 BasicTeX，再运行 `sudo tlmgr install latexmk revtex`），装完**新开一个终端**。
  - Linux：`sudo apt install latexmk texlive-latex-extra texlive-publishers`。
  - 装好后重新运行 `pnpm paper open`。`pnpm paper doctor` 会检查装好了没有。服务器的报错和 `paper doctor` 给的是同一段建议。
- **缺某个 TeX 宏包时**，编译错误里会提示要装哪个包；用 TinyTeX 时也有说明。
- **latexmk 记住了上一次失败**而不肯重新编译的情况，现在会自动恢复。
- **有可恢复的 LaTeX 错误时**，也会显示 PDF（引用和交叉引用照样解析），同时列出错误。
- **演示模式**：“编译”显示一份事先用 latexmk 编好的示例 PDF，按钮上写“示例 PDF”。PDF 上方有一句说明：这份 PDF 不会随你的修改更新，PDF 和正文之间的跳转是近似的；完整模式会真正编译。

### 没懂怎么用

- **新手引导**（只在演示模式里，绝不在你自己的论文上运行）：第一次打开时右下角有一张小卡片“第一次用？花 5 分钟走一遍引导”。一共 8 步，每步用光圈指出真实的按钮，旁边一张小卡片说明这一步做什么，再给一个“动手试试”的小任务：
  1. 认识左边四步，点 ② 资料；
  2. 点一句高亮的句子，打开它的卡片；
  3. 按 ⌘I，输入“把基线放在前面”，回车，再按 ⌘Enter 接受；
  4. 单独一行写一句中文想法，按 ⌘Enter 变成英文句子，再按 Tab；
  5. 输入 “The gain”，按 ⌥/ 看灰色补全，Tab 接受；
  6. 把 8,710 改成 9,000，看到它被标成“找不到来源”；
  7. 在 ① 里写下一句话故事并勾选，起草，再到 ③ 里接受一句；
  8. 在 ④ 里运行投稿检查，再点编译看示例 PDF。
  按键会按你的系统显示（Mac 上是 ⌘ / ⌥）。文字跟着界面语言（中文 / English）。
- **“?” 按钮**现在是一个菜单：快捷键、新手引导（中途跳过后显示“继续新手引导（第 n/8 步）”和“从头开始”）、重置示例论文（只在演示模式，会先问你）。
- 在完整模式里点“新手引导”，会在新标签页里打开演示论文并开始引导，不会动你的论文。
- README（中英文）开头加了“第一步”：先试演示和引导，再装 TeX，再按快速开始操作。

## 2. 界面重新分组

你用过 `?mock=1` 后说界面太乱。现在：

- **左侧竖栏只有四步**，按写作顺序：
  - ① 构思：你自己写的五项、其他讲法、章节和段落规划、起草。
  - ② 资料：事实（每个数字的来源文件和 SHA）和文献。
  - ③ 待办：等你审阅的 AI 句子、占位符、审稿人问题，合成一张清单，按文中顺序。
  - ④ 检查：投稿检查、一致性、术语、图表规划、AI 使用声明、和 Overleaf 同步。
- **顶栏简化**：编译、同步、检查、“模拟 AI”标记（没有 API key 时）、⚙ 设置、?。
- **⚙ 设置抽屉**：文风、界面语言、主题、归属热图、是否显示 PDF、本次 API 费用。
- **窗口窄时**，编辑器优先：PDF 或面板会让到边上，只留一条细边，点一下就回来。你主动打开的那一个不会被收起。
- 整个界面有完整的中文翻译，浅色和深色主题都检查过（截图检查没有溢出）。

## 3. 新功能

用大白话说每个功能做什么：

- **投稿检查**：投稿前一键列出所有问题。会拦住投稿的有：没审阅的 AI 句子、占位符、中文意图行、找不到来源的数字、正文里还写着旧值的过期数字、.bib 里没有的引用、LaTeX 错误、缺少 AI 使用声明。点每一行跳到那句话，跨文件也行。
- **一致性**：同一个核心数字在摘要、正文、结论、图注里有没有写得不一样（比如 96.94% 和 96.9%），有没有把“倍数”写成“百分比”，有没有漏掉条件（比如“在验证样本上”）。
- **术语**：每个定义过的术语第一次出现在哪里，有哪些不同写法需要统一，缩写是否在定义之前就用了。
- **图表规划**：每张图的作用、支撑哪个结论、图注检查清单、正文里是否按顺序引用了它。
- **推导数字**：“假径迹少 2.5 倍”这样的数，如果确实是两个事实之比（或之差），并且句子谈的就是这两个量、方向也写对了，就算有来源。
- **文件切换**：用 `\input` 拆成多个文件的论文，可以在顶栏的文件名处切换文件，每个文件旁边有句子数。所有检查覆盖全部文件。
- **恢复旧版本**：每句话的每个版本都保留，在句子卡片的历史里可以放回以前的版本。放回 AI 写的版本时会重新核对数字，过时的数字会被标红；放回 AI 草稿需要重新审阅。
- **分析仓库监视**：你重跑分析、`results/` 里的文件变了，app 会自动重新读取事实，把变了的标为“过期”，并提示哪些文件变了。还写着旧值的句子会出现在一致性和投稿检查里。

## 4. 稳定性工作

- **真实 API 路径的验证**：在本地搭了一个假的 Anthropic API 服务器，让真正的 Anthropic 客户端和 Agent SDK 代码去连它（不是模拟 AI 的替身）。发现并修好了：

## 5. 第二轮对抗式审查：发现的问题和修复

第二轮审查从四个角度（科研诚信、数据安全、安全、易用性）找问题。每个问题都先写一个会失败的测试复现，再修好，测试保留下来防止再犯。每条一句话：

**科研诚信（AI 不能编数字、不能把没审阅的文字推给合作者）**

- R2-I-1（最严重）：在 VS Code 或 Overleaf 里改了一个词，没审阅的 AI 句子就不再拦推送了。现在外部修改保留“待审阅”状态。
- R2-I-2 / R2-I-10：过期数字的拦截在重启、改了句子里别的词、数字有歧义、字段改名后会消失。现在只要句子还写着旧值就一直拦。
- R2-I-3：和两个无关事实之比碰巧相等的编造数字被当成“有来源”。现在推导数字必须写成对应的形式，并且句子要谈到这两个量。
- R2-I-4：把两种方法的数字对调（结论反过来）也能通过。现在会核对数字属于哪种方法。
- R2-I-5：“高 60%”和“低 60%”都被接受。现在推导数字也检查方向。
- R2-I-6：“快 3 倍”被一个“种子数 = 3”的事实当成来源。现在“倍数”只能对应比值类事实。
- R2-I-7：“N out of M”里的 M 没有检查。现在 M 必须是整数或对应一个计数事实。
- R2-I-8：投稿检查报的是上一次编译的结果，不是当前文字的。现在会检查编译是否对应当前文字。
- R2-I-9：用 `\import`/`\subimport` 引入的文件没被检查，表格和标题里的占位符也漏掉了。现在都会检查。
- R2-I-11：单个种子的数值被写成总体结果时没有提示。现在一致性检查会标出来。
- R2-I-12：“两倍”能对应 1.55 的比值。现在文字或整数倍数必须在真实比值的 10% 以内。

**数据安全（绝不丢字）**

- R2-DATA-1：app 自己的定时保存会覆盖你在别处对文件的修改。现在先检查磁盘，不覆盖。
- R2-DATA-2：断线重连后，一个从没发出去的修改可能被丢掉。现在只考虑确实发出去的修改。
- R2-DATA-3：在磁盘重新加载的瞬间按 ⌘S，接下来打的字会被抹掉。修好了。
- R2-DATA-4：切换文件或关闭标签页时，没发出去的文字会丢。现在先保存，关页面前会提醒。
- R2-DATA-5：重连后打开文件的请求可能被吞掉，页面卡住。现在会重发直到收到回应。
- R2-DATA-6：服务器重启期间同一行在编辑器和磁盘上都改了，有一边会丢。现在两行都保留，不丢任何一边。
- R2-DATA-7：两处相距很远的修改合并失败，整个用磁盘版本覆盖。现在能精确合并。

**安全（本地服务器不能成为攻击入口）**

- SEC2-1：一段数字特别密集的段落能让服务器卡住几秒（算法是平方级的）。现在是线性的。
- SEC2-2：术语检查的正则表达式遇到超长单词会很慢。修好了。
- SEC2-3 / SEC2-4：.bib 里叫 `constructor` 的引用键会被误当成“已确认”（JavaScript 的一个常见陷阱）；以点开头的隐藏文件会被服务器发出去。两个都修好了。新加的接口都有回归测试。

**易用性**

- UX2-1：有可恢复 LaTeX 错误时不显示 PDF。现在显示 PDF 并列出错误。
- UX2-2 到 UX2-10：编译栏把错误放到看得见的地方；面板和 PDF 让位时留一条细边而不是直接消失；没有 PDF 时不再打开空白 PDF 面板；Mac 上句子卡片的按键提示；设置里的 PDF 开关；服务器断开时的提示；没装 latexmk 时的提示；文字对比度。

## 9. 已知的限制

- 演示模式的 PDF 是固定的示例，不随修改更新；PDF 和正文之间的跳转是近似的。
- 数字归属检查：只有写法很明确时（如“96.94% for acorn”）才拦截；只靠“离数字最近的名字”判断时只给提醒，提醒不会阻止你接受 AI 句子。
- 单个种子的数值写成总体结果时，AI 句子的即时检查仍会放行，只有一致性检查和投稿检查会标出来。
- 超长句子没有硬性长度上限（算法已经是线性的，所以目前没有必要）。
- 新手引导只在演示模式里；完整模式只有第一次打开时的四步提示。
- 窗口较窄时（比如 1440 像素宽），PDF 和步骤面板不能同时显示，后打开的那一个优先，另一个留一条细边。
- 真实 API、Agent SDK、Overleaf、macOS 钥匙串和 Canto 稿件都还没在真实环境里验证（见第 7 节）。
